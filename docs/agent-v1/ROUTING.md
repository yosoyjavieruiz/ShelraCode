# Capability-aware routing

Routing applies privacy and cost hard gates before quality. Local candidates
remain first-class. `strict-zero` never selects an unverified paid route.

For coding, a measured advanced candidate is preferred. If no advanced local
candidate exists, the TUI may use the progressive fallback only when the
objective names multiple workspace paths and the candidate has measured
workspace-reader/continuation capability. A blocked task with no mutation may
escalate; a task that already mutated the workspace never silently changes
models.

Hardware fit answers “can it run?”; capability probes answer “can it behave?”
Both are required for an autonomous coding label.
