# Guía de pruebas de LocalCode

Ejecuta los prompts en orden, desde los más básicos hasta los más complejos.
En cada caso, compara el comportamiento real con la expectativa indicada.

| Prompt                                                                                                                                                                                                                  | Qué debemos esperar                                                                                                                                                                                                                |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Hola`                                                                                                                                                                                                                  | Respuesta conversacional normal. No debe explorar el repositorio, llamar herramientas, ejecutar comandos ni modificar archivos.                                                                                                    |
| `¿Qué es GGUF?`                                                                                                                                                                                                         | Respuesta basada en conocimiento general. No debe realizar operaciones sobre el repositorio.                                                                                                                                       |
| `¿Qué lenguaje usa este proyecto?`                                                                                                                                                                                      | Debe revisar evidencia relevante del proyecto, como manifiestos o archivos de configuración, y responder correctamente. No debe escribir nada.                                                                                     |
| `¿Dónde está implementado createSession?`                                                                                                                                                                               | Debe buscar el símbolo, leer el archivo relevante y responder con su ubicación. No debe modificar archivos.                                                                                                                        |
| `Explica cómo funciona la autenticación de este proyecto.`                                                                                                                                                              | Debe consultar los archivos, callers y pruebas relevantes, y dar una explicación coherente basada en evidencia. No debe modificar archivos.                                                                                        |
| `Analiza cómo añadir OAuth y dame un plan. No modifiques nada.`                                                                                                                                                         | Debe explorar el repositorio, identificar archivos afectados, riesgos y pasos de implementación. Debe permanecer en modo de solo lectura.                                                                                          |
| `Revisa auth.ts en busca de posibles errores. No modifiques nada.`                                                                                                                                                      | Debe leer el archivo, señalar problemas concretos y explicar la evidencia. No debe editar ni ejecutar una implementación.                                                                                                          |
| `Inspecciona .agents/skills/example/SKILL.md y dime qué contiene.`                                                                                                                                                      | Debe usar una lectura de archivo para esa ruta. Si intenta listar un archivo como si fuera un directorio, debe reconocer el error, corregir la herramienta y continuar sin detener la tarea.                                       |
| `Encuentra la configuración de sesiones aunque no recuerde la ruta.`                                                                                                                                                    | Debe buscar de forma acotada, encontrar evidencia nueva y continuar. No debe adivinar rutas indefinidamente ni terminar sin explicación.                                                                                           |
| `Cambia "hello" por "hello world" en src/message.ts y verifica el cambio.`                                                                                                                                              | Debe inspeccionar el archivo, hacer una edición precisa, comprobar el resultado y reportar qué cambió. No debe sobrescribir cambios ajenos.                                                                                        |
| `Corrige el test de autenticación que está fallando y asegúrate de que pase.`                                                                                                                                           | Debe ejecutar la prueba, leer el fallo, inspeccionar la implementación, corregirla, ejecutar la prueba otra vez y declarar éxito sólo cuando pase.                                                                                 |
| `Añade multiply(a, b) y sus pruebas unitarias siguiendo las convenciones existentes.`                                                                                                                                   | Debe revisar las convenciones del proyecto, implementar la función, actualizar exports o callers si hace falta, añadir pruebas y verificar que pasen.                                                                              |
| `Añade una funcionalidad que afecte varios archivos y actualiza sus pruebas.`                                                                                                                                           | Debe descubrir primero la arquitectura y los callers, crear un plan cuando sea necesario, modificar sólo los archivos relacionados y verificar la funcionalidad completa.                                                          |
| `Analiza la arquitectura de autenticación. Migra el token lifecycle preservando compatibilidad, actualiza todos los callers, agrega regresiones, ejecuta tests/typecheck/build, corrige fallos y revisa el diff final.` | Debe trabajar de principio a fin: entender el objetivo, descubrir contexto, planificar, editar varios archivos, ejecutar verificaciones, corregir fallos, revisar el diff y completar sólo cuando los criterios estén satisfechos. |
