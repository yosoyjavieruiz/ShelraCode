## Intent

Rebuild the user-facing terminal interface around one calm, conversation-first
workspace. The UI will make the agent's current task, route, privacy and
composer obvious while moving navigation, model management, settings, routing,
usage and review into temporary full-screen workspaces or focused overlays.

The current application is functional enough to serve as a presentation host,
but its default wide layout still renders a permanent sidebar and inspector,
its centers are mostly string lists, and several claimed interactions are
read-only. This design addresses those presentation and interaction failures
without rewriting routing, providers, model discovery, privacy, storage or the
agent loop.

## Product constraints

- Canvas remains exactly `#000000`.
- Primary accent remains exactly `#8B5CF6`.
- Purple is reserved for focus, selection, brand and primary action.
- Local execution is first-class; strict-zero remains fail-closed.
- No fake models, provider health, quota, route decisions or settings.
- TUI business logic remains outside leaf components.
- OpenTUI Solid remains the renderer and `renderer.destroy()` remains the
  lifecycle boundary.
- Existing dirty work is preserved; no reset, checkout, blanket staging or
  unrelated refactor is allowed.

## Chosen approach: Minimal Canvas

Three concepts are evaluated before the live shell is finalized:

1. **Minimal Canvas** — one quiet top line, dominant transcript, anchored
   composer and compact footer. Navigation and workspaces are transient.
2. **Context Ribbon** — the same canvas plus a one-row task ribbon that appears
   only while a task is active and disappears while idle.
3. **Adaptive Edge Chrome** — a temporary left command rail and right detail
   drawer that appear only after an explicit command or an active task.

Minimal Canvas wins because it preserves the central product action at every
width, removes the current dashboard failure, and can still expose every
existing service through the command palette and focused workspaces. Context
Ribbon behavior is retained as a conditional status line for active tasks;
Adaptive Edge Chrome is implemented only as an explicit overlay, never as
permanent width reservation.

## Information architecture

The app has four presentation layers:

```text
Application shell
  Top chrome: brand, repository/branch, compact route/privacy state
  Main workspace: conversation OR one full-screen center
  Composer: focused editor, context/mode/route hints, submit/cancel state
  Footer: actionable status and keyboard hints
  Overlay stack: palette, model picker, confirmation, detail, help
```

Default surface is `conversation`. Centers replace the main workspace and
return with Escape:

- Models: searchable selectable list, active model, local/free sections,
  capability and privacy detail.
- Providers: list/detail health, freshness, quota and policy language.
- Routing: readable gate sequence, selected route, rejected reasons and route
  event history.
- Usage: quota bars only when backed by current provider snapshots.
- Settings: searchable category/list editor for settings that have real backing.
- Sessions: current and persisted session list when storage provides records.
- Changes: file list and OpenTUI diff view; no fake review actions.
- Privacy, Context, Plan, Doctor, Checkpoints and Help: semantic adapters over
  existing control-plane data.

The command registry remains the single source for slash aliases, palette
entries, shortcuts, help and navigation. Palette search uses ranked fuzzy
matching, category labels, selected-row focus, descriptions and shortcuts.

## State and data flow

`AppShell` owns only presentation state and orchestration:

- active screen and overlay stack;
- focused region and selected row;
- composer text and draft history;
- expanded activity IDs and sticky-scroll state;
- display settings and responsive layout profile.

Control-plane calls continue to populate typed state. New presentation
adapters normalize live domain values into semantic rows and details. No
provider-specific response type crosses into a leaf component.

Streaming keeps the current Markdown block incremental. Activity events are
grouped by phase/tool where possible, collapsed by default, and expanded with
Enter. Auto-follow pauses when the user scrolls away from the bottom and
surfaces a textual `↓ New activity` affordance.

## Responsive contract

| Width  | Contract                                                                        |
| ------ | ------------------------------------------------------------------------------- |
| 80x24  | conversation, composer, critical route/privacy/error only; no rail or inspector |
| 100x30 | same canvas with one additional status/detail row when it fits                  |
| 120x40 | full-width conversation or center; overlays may use up to 88% width             |
| 160x50 | conversation remains dominant; optional explicit drawer only                    |
| 200x60 | generous transcript measure; no permanent dashboard columns                     |

Information is removed in this order: decorative copy, timestamps, secondary
metrics, long provider labels, optional hints. Conversation, composer, current
task, error/approval, route/model and privacy remain.

## Accessibility and lifecycle

- `NO_COLOR` preserves labels, symbols, focus prefixes and state words.
- Focus is visible through selection marker/text treatment, not color alone.
- Reduced motion disables decorative transitions and spinner animation.
- ASCII-safe glyphs are used for critical states.
- Escape closes the highest overlay first, then returns from a center, then
  cancels/clears a composer draft according to explicit focus state.
- Ctrl+C cancels active work; while idle it exits. Normal, exception, SIGTERM
  and Ctrl+C paths restore terminal state through renderer-owned cleanup.

## Out of scope

No new provider adapter, routing policy, model engine, storage schema, agent
reasoning behavior, billing behavior, hosted account, or remote telemetry is
introduced. A UI action that lacks an existing service remains absent or is
shown as a clearly disabled informational state.
