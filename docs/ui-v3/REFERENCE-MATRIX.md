# LocalCode UI V3 reference matrix

Research captured 2026-08-23. Sources were checked against current official documentation or official repositories. The references inform interaction principles; LocalCode does not copy their identity, code, or assets.

| Product / source                                                                                           | Screen or behavior studied                                | What works                                                                         | What does not translate directly                                              | LocalCode principle to adapt                                                | Principle to avoid                                               |
| ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| [OpenCode CLI](https://opencode.ai/docs/cli/)                                                              | Full-screen TUI, session and model entry points           | Terminal-native focus; conversation remains the primary surface                    | OpenCode's command vocabulary and provider model are different                | Keep depth inside a terminal workspace and make actions discoverable        | Do not imply OpenCode parity or copy its branding                |
| [Claude Code CLI](https://docs.anthropic.com/en/docs/claude-code/cli-usage)                                | Interactive prompt and slash-command workflow             | Operational controls stay close to the prompt                                      | Claude-specific account, tool, and billing semantics                          | Use slash input as a low-friction command entry point                       | Do not expose provider assumptions as LocalCode policy           |
| [OpenAI Codex slash commands](https://github.com/openai/codex/blob/main/codex-rs/tui/src/slash_command.rs) | Authoritative command enum and presentation order         | A named command registry makes help and autocomplete coherent                      | Codex's command set is not LocalCode's feature set                            | One registry feeds palette, slash actions, shortcuts, and help              | Do not maintain separate shortcut and slash catalogs             |
| [Gemini CLI commands](https://github.com/google-gemini/gemini-cli/blob/main/docs/reference/commands.md)    | REPL commands, help, shell/at command model               | Command discovery reduces memorization                                             | Gemini's shell mode and remote service assumptions differ                     | Keep commands searchable and explain the next action                        | Do not add commands that have no working LocalCode action        |
| [Raycast search bar](https://manual.raycast.com/search-bar)                                                | Root search, fuzzy ranking, recents                       | Search is a single confident entry point; ranking rewards exact and recent actions | Desktop launcher density and mouse affordances do not fit every terminal size | Make Ctrl+P one coherent palette with predictable ranking                   | Do not turn every workspace into a card grid                     |
| [Raycast action panel](https://manual.raycast.com/action-panel)                                            | Contextual action surface and Escape back behavior        | Primary action and contextual actions remain together                              | Raycast's action taxonomy is desktop-specific                                 | Use Enter for the primary action and Escape to reduce depth                 | Do not hide essential actions behind mouse-only panels           |
| [Linear display options](https://linear.app/docs/display-options)                                          | Density and progressive disclosure                        | Calm hierarchy and user-controlled information density                             | Linear's issue/project navigation is not a terminal agent workflow            | Let conversation dominate; expose details only when needed                  | Do not reserve dashboard chrome in the default shell             |
| [Warp command palette](https://docs.warp.dev/terminal/command-palette)                                     | Global palette and filters                                | Searchable actions have stable names and keyboard paths                            | Warp's cloud/product model is outside LocalCode's scope                       | Group commands by intent and make the search field the focus target         | Do not show decorative actions without a real handler            |
| [Warp blocks](https://docs.warp.dev/terminal/blocks/block-basics)                                          | Command/output grouping and sticky activity               | Repeated terminal activity becomes legible as one unit                             | LocalCode tool events carry agent semantics, not shell blocks                 | Group tool activity and expand details on demand                            | Do not let raw tool logs dominate the transcript                 |
| [Zed command palette](https://zed.dev/docs/command-palette)                                                | Universal command search                                  | One command vocabulary reduces mode confusion                                      | Zed has an editor buffer and command registry outside this TUI                | Derive help and palette rows from the same registry                         | Do not introduce a second editor-like navigation system          |
| [Zed agent panel](https://zed.dev/docs/ai/agent-panel)                                                     | Agent message editor and streamed tool indicators         | Prompt, model selection, and tool progress are visually related                    | Zed's pane model is not the LocalCode default architecture                    | Keep model/route state near the composer without a permanent inspector      | Do not make the composer a secondary footer control              |
| [Yazi quick start](https://yazi-rs.github.io/docs/quick-start/)                                            | Focus, selected cursor, h/j/k/l and reversible navigation | Terminal state is obvious and movement is learnable                                | Yazi's file-manager panes are not required for conversation                   | Show focus and give every transient surface an Escape path                  | Do not add a permanent file-manager rail to the chat shell       |
| [Lazygit guide](https://lazygit.dev/docs/guide/)                                                           | Tabs, filters, Enter drill-in, Escape back, `?` help      | Dense screens work when the active region and next key are visible                 | Git operations are not being added to the product                             | Use explicit footers and named workspaces for dense views                   | Do not rely on users memorizing opaque single-key commands       |
| [Superfile tutorial](https://superfile.dev/getting-started/tutorial/)                                      | Focused panels, search, command bar                       | The current focus and mode are continuously legible                                | Superfile's panel navigation would reintroduce the dashboard problem          | Use focusable rows and a compact action contract                            | Do not make mouse events the only activation path                |
| [K9s repository](https://github.com/derailed/k9s)                                                          | Resource-oriented terminal monitoring                     | Live state and health are more useful than decorative metrics                      | Kubernetes resources and refresh loops are not LocalCode domain objects       | Provider/model workspaces must render live freshness and health             | Do not display fake quota or health values                       |
| [OpenTUI Solid bindings](https://opentui.com/docs/bindings/solid/)                                         | `testRender`, dimensions, Portal, keyboard hooks          | The renderer already supplies native primitives for testing and focus              | OpenTUI has no browser accessibility tree                                     | Use native Markdown, Diff, ScrollBox, focusable rows, and frame captures    | Do not rebuild native primitives with raw string layout          |
| [OpenTUI ScrollBox](https://opentui.com/docs/components/scrollbox/)                                        | Sticky scroll and viewport culling                        | Streaming can follow the bottom without rerendering every view                     | Scroll position must still be verified in the real terminal                   | Pause implicit follow when users review history; preserve composer position | Do not hide all review affordances behind an invisible scrollbar |
| [OpenTUI Diff](https://opentui.com/docs/components/diff/)                                                  | Unified/split diff primitive and line numbers             | Native diff rendering gives consistent code review density                         | One diff instance represents one file patch                                   | Prefer the native primitive and retain a safe raw fallback                  | Do not ship an unbounded raw payload as the default error state  |

## Synthesis

The shared pattern is a small primary surface plus explicit transient depth: search, select, inspect, return. LocalCode uses that pattern with its own Obsidian Violet identity, while privacy and cost gates remain in the existing core routing path.
