# LocalCode Local Model Hub — Official Research Snapshot

Checked: 2026-08-23. Sources are official documentation or official
repositories. Volatile CLI/API behavior must be rechecked before adding a new
adapter.

| Source                                                                                                                 | Fact checked                                                                                                                                                                  | Implementation consequence                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [llama.cpp repository](https://github.com/ggml-org/llama.cpp)                                                          | The current project documents direct Hugging Face model execution and a unified `llama` CLI, including `llama serve` for a local API                                          | Treat llama.cpp as the managed cross-platform runtime target; do not require LM Studio for local execution                                                |
| [llama-server documentation](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)                 | `llama-server` accepts local model paths, HF repo/quant arguments, exposes `/health`, and serves OpenAI-compatible endpoints on localhost                                     | Managed runtime needs binary detection, explicit model path/repo, health polling, owned port and bounded shutdown                                         |
| [Hugging Face download guide](https://huggingface.co/docs/huggingface_hub/guides/download)                             | `snapshot_download` caches snapshots and supports `allow_patterns`, `ignore_patterns`, revisions and local directories                                                        | Catalog downloads must be revision-aware, filter model formats, persist the resolved revision and avoid cloning arbitrary repositories                    |
| [Hugging Face file download reference](https://huggingface.co/docs/huggingface_hub/en/package_reference/file_download) | `snapshot_download` supports `dry_run`, `local_files_only`, cache directories and explicit revisions; incomplete/offline snapshots have defined failure behavior              | Add dry-run-like metadata, offline mode and a structured download failure rather than silently retrying forever                                           |
| [Hugging Face gated models](https://huggingface.co/docs/hub/models-gated)                                              | Gated repositories require an authenticated user/token after access is granted                                                                                                | Public discovery can be unauthenticated; gated downloads need an explicit user token and must never log it                                                |
| [llmfit CLI](https://github.com/AlexsJones/llmfit/blob/main/docs/cli.md)                                               | `llmfit --json system`, `recommend --json`, `fit`, and `plan ... --json` expose machine-readable hardware and per-path feasibility; `plan` includes GPU and CPU-offload paths | Parse only the stable fields LocalCode needs, retain unknown fields, and represent `GPU`, `GPU + RAM`, `CPU`, `STRETCH`, and `NOT_VIABLE` as fit outcomes |
| [MLX documentation](https://ml-explore.github.io/mlx/)                                                                 | MLX uses Apple Silicon unified memory and supports CPU/GPU devices                                                                                                            | MLX is a platform-specific local runtime candidate, not a mandatory dependency on Windows/Linux                                                           |
| [MLX-LM server](https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/SERVER.md)                                       | `mlx_lm.server --model <local path or HF repo>` serves an OpenAI-like API on localhost and lists models via `/v1/models`                                                      | A future MLX adapter can share the local HTTP contract while keeping MLX detection/platform gating separate                                               |
| [LM Studio server CLI](https://lmstudio.ai/docs/cli/serve/server-start)                                                | `lms server start` starts a localhost server with explicit port/bind; default bind is localhost                                                                               | LM Studio is an external local runtime; detect/connect when present, never install or require it                                                          |
| [LM Studio OpenAI-compatible tools](https://lmstudio.ai/docs/developer/openai-compat/tools)                            | LM Studio supports `/v1/chat/completions`, tool calls and local model loading through its server/CLI                                                                          | Tool-capability metadata belongs to the local runtime/model contract, not cloud privacy/quota gates                                                       |
| [Ollama API introduction](https://docs.ollama.com/api/introduction)                                                    | Ollama serves a local API at `http://localhost:11434/api` and provides model interaction APIs                                                                                 | Ollama remains an external adapter with local ownership and no LocalCode usage quota                                                                      |
| [Ollama chat API](https://docs.ollama.com/api/chat)                                                                    | Chat requests include model, messages, tools, streaming and runtime options; responses include generation timing fields                                                       | Normalize Ollama timing into local benchmark observations and preserve tool support separately from cloud usage                                           |

## Research decisions

- Use built-in `fetch`, filesystem streams and SQLite rather than adding the
  Python `huggingface_hub` package to the Bun application. The service mirrors
  the documented Hub REST behavior and remains injectable for tests.
- Treat HF metadata as discovery input, not as proof that a model is locally
  runnable. Variant format, size, revision, license, gated status and fit are
  separate fields.
- Use `llmfit` as the hardware intelligence provider and keep a basic fallback;
  do not recreate a GPU/RAM model matrix in TypeScript.
- Keep remote quota/cost/privacy metadata on `RemoteProviderTarget` only.
- Managed runtime process ownership is explicit. No `curl | sh`, arbitrary
  repository scripts or implicit binary downloads are permitted.
